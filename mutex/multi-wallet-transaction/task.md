# 030. Транзакция над несколькими кошельками

**Сложность:** Hard

**Темы:** несколько блокировок, согласованный снимок, принцип «всё или ничего»

## Условие

Реализуйте набор кошельков с начально заданными балансами:

```go
type WalletID string

type Ledger struct { /* внутреннее состояние */ }

func NewLedger(initial map[WalletID]int64) *Ledger
func (l *Ledger) Apply(deltas map[WalletID]int64) bool
func (l *Ledger) Snapshot(ids []WalletID) map[WalletID]int64
```

`NewLedger` создаёт кошельки из `initial` и сохраняет собственную
копию начальных балансов: последующее изменение переданной карты не
влияет на `Ledger`. Начальные балансы неотрицательны. После создания
набор ID остаётся постоянным; менять баланс может только `Apply`.
Все ID, передаваемые в `Apply` и `Snapshot`, уже существуют в
`Ledger`.

`deltas` задаёт изменение каждого указанного кошелька: отрицательное
значение списывает средства, положительное зачисляет. Сумма всех
`deltas` всегда равна нулю, поэтому успешная операция сохраняет общую
сумму денег. Кошельки, отсутствующие в карте, не изменяются.

`Apply` сначала определяет, останется ли баланс **каждого** затронутого
кошелька неотрицательным. Если да, метод применяет **все** изменения и
возвращает `true`. Если хотя бы одному кошельку не хватает денег, метод
возвращает `false` и **не меняет ни один** баланс. Другие конкурентные
операции не должны видеть частично применённую транзакцию.

`Snapshot(ids)` возвращает новую карту с балансами перечисленных ID.
Все значения в ней должны относиться к одному согласованному состоянию:
если одновременно выполняется `Apply`, затрагивающий эти кошельки,
снимок видит состояние целиком **до** него или целиком **после**.
Изменение возвращённой карты не меняет кошельки.

`Apply` и `Snapshot` могут вызываться конкурентно. Операции,
затрагивающие непересекающиеся наборы кошельков, должны иметь
возможность выполняться параллельно: не сериализуйте все `Apply`
одной общей глобальной блокировкой. Встречные операции с общими
кошельками не должны приводить к взаимной блокировке.

## Ограничения

- Все кошельки создаются заранее; после `NewLedger` новые ID не
  добавляются.
- В одном вызове `Apply` или `Snapshot` участвует не более 100 ID.
- Пустой `deltas` — успешная операция без изменений; пустой `ids`
  даёт пустой снимок.
- Повторяющийся ID в `ids` даёт одну запись в возвращённой карте.
- Вызывающий код не изменяет `initial`, `deltas` или `ids` во время
  соответствующего вызова. Переполнение `int64` не проверяется.
- Используйте стандартную библиотеку Go. Не устанавливайте порядок
  выполнения горутин через `time.Sleep` или активное ожидание.

## Примеры

```text
Вход: initial={A:5, B:3, C:0}
      Apply({A:-4, B:-2, C:6})
      Snapshot([A,B,C])
      Apply({A:-2, C:2})
      Snapshot([A,B,C])
Выход: true
       {A:1, B:1, C:6}
       false
       {A:1, B:1, C:6}
Пояснение: второе Apply отклонено целиком, потому что у A осталась 1
          единица, а списать требуется 2.
```

```text
Вход: initial={A:5, B:0}
      параллельно: Apply({A:-5, B:5}) и Snapshot([A,B])
Допустимый снимок: {A:5, B:0} или {A:0, B:5}
Недопустимый снимок: {A:0, B:0} или {A:5, B:5}
```
