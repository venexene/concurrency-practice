# 029. RW-блокировка с приоритетом писателей

**Сложность:** Hard

**Темы:** `sync.Mutex`, `sync.Cond`, приоритет писателей, FIFO

## Условие

Реализуйте блокировку `WriterFirstRWLock` с API:

```go
func NewWriterFirstRWLock() *WriterFirstRWLock
func (l *WriterFirstRWLock) RLock()
func (l *WriterFirstRWLock) RUnlock()
func (l *WriterFirstRWLock) Lock()
func (l *WriterFirstRWLock) Unlock()
```

Несколько горутин могут одновременно владеть блокировкой на чтение.
Писатель владеет ей эксклюзивно: пока он находится между `Lock` и
`Unlock`, ни читатель, ни другой писатель войти не могут. Вызов
`RUnlock` завершает одно успешное чтение, `Unlock` — одну успешную
запись.

**Приоритет писателей:** как только писатель зарегистрировался в
ожидании, новые вызовы `RLock` не проходят, пока не завершатся уже
активные читатели и очередь ожидающих писателей не опустеет. Читатели,
которые вошли раньше регистрации писателя, могут закончить свою работу.
Ожидающих писателей допускайте в порядке FIFO **по регистрации**,
а не по порядку запуска горутин.

Все методы могут вызываться одновременно. При конечных критических
секциях и продолжающемся выполнении горутин зарегистрированные
писатели должны продвигаться по очереди. Ожидающий читатель получает
доступ после ухода писателя и опустошения очереди писателей. Если новые
писатели прибывают без конца, момент опустошения очереди не гарантирован
самим правилом приоритета.

## Ограничения

- Используйте `sync.Mutex` и `sync.Cond`; `sync.RWMutex` запрещён.
- Вызовы корректно сбалансированы: каждому успешному `RLock` следует
  `RUnlock`, каждому успешному `Lock` — `Unlock`.
- Рекурсивный захват, превращение чтения в запись и ошибочные
  `Unlock`/`RUnlock` не требуются.
- Создавайте объект через конструктор; нулевое значение типа не
  обязано работать.
- Используйте стандартную библиотеку Go. Не устанавливайте порядок
  горутин через `time.Sleep` или активное ожидание.

## Пример

`start` запускает вызов в отдельной горутине, `join` ждёт его
завершения. Фраза «W зарегистрировался» означает, что вызов `Lock`
уже встал в очередь, а не только что была запущена его горутина.

```text
Вход: R1 захватил чтение; W зарегистрировался и ждёт;
      R2 запросил чтение; R1.RUnlock();
      W вошёл и затем вызвал Unlock()
Выход: порядок входа в критическую секцию [R1, W, R2]
```
