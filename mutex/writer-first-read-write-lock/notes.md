# 029. RW-блокировка с приоритетом писателей

## Инсайт

Одного признака ожидающих писателей недостаточно: когда очередной
писатель уже вошёл, он больше не ожидает, но читатели всё равно не
должны проходить. Поэтому состояние активного писателя и очередь
ожидающих учитываются отдельно. Билеты задают порядок допуска
писателей.

## Решение

Храню число активных читателей `readers`, признак активного писателя
`isWriterActive`, число ожидающих писателей `waitingWriters` и два
счётчика билетов. Все эти поля защищены мьютексом `cond.L`.

`RLock` ждёт, пока нет активного писателя и очередь писателей пуста,
затем увеличивает `readers`. Последний `RUnlock` будит ожидающих.
`Lock` получает билет и ждёт ухода читателей и своей очереди;
перед возвратом отмечает писателя активным. `Unlock` освобождает
блокировку, переводит номер обслуживаемого билета и будит ожидающих.

Проверки и изменения полей занимают `O(1)` работы; ожидание и стоимость
пробуждения зависят от числа ожидающих горутин. Сам объект использует
`O(1)` памяти и не создаёт дополнительных горутин.


## Что важно запомнить

- `waitingWriters` считает ожидающих, но не активного писателя.
  `RLock` должен учитывать оба состояния.
- Билет выдаётся под мьютексом. Писатель входит только когда его билет
  совпадает с обслуживаемым; номер продвигается после `Unlock`.
  Так писатели проходят FIFO по регистрации.
- `sync.Cond` может разбудить горутину, которой ещё нельзя войти.
  Поэтому условия в `RLock` и `Lock` проверяются в цикле.
- Приоритет может задерживать читателя, пока очередь писателей не
  опустеет. Бесконечный поток новых писателей не гарантирует такого
  момента; это следует из заданного правила приоритета.

## Проверка

Тесты проверяют совместное чтение, исключительность писателя,
приоритет зарегистрированного писателя перед новым читателем,
FIFO писателей и завершение смешанной нагрузки без одновременного
чтения и записи. В тестах приоритета регистрация писателя
наблюдается под внутренним мьютексом, а не предполагается по
задержке времени.

```sh
go test -race -timeout 15s ./mutex/writer-first-read-write-lock
go test -race -count=20 -timeout 30s ./mutex/writer-first-read-write-lock
```

Оба запуска прошли, race detector не сообщил о гонках. Проверенные
сценарии не являются доказательством для всех расписаний горутин.

## Оценка

Ошибок в текущем решении в пределах проверенного контракта не обнаружено.
