# 028. Очередь на условных переменных

**Сложность:** Medium

**Темы:** `sync.Mutex`, `sync.Cond`, ограниченный буфер, закрытие

## Условие

Реализуйте ограниченную FIFO-очередь с API:

```go
type Queue struct { /* внутреннее состояние */ }

func NewQueue(capacity int) *Queue
func (q *Queue) Put(x int) error
func (q *Queue) Get() (int, error)
func (q *Queue) Close()
```

`Put` добавляет значение в конец очереди. Если очередь полна, вызов
ждёт свободного места. `Get` извлекает самый старый элемент. Если очередь
пуста, вызов ждёт элемента. Ноль — обычное значение `int`, а не признак
пустой очереди. Методы одного экземпляра можно вызывать одновременно.

`Close` запрещает новые добавления и будит все ожидающие `Put` и
`Get`. Повторный `Close` безопасен. Значения, принятые до закрытия,
остаются в очереди: `Get` выдаёт их в порядке FIFO, а после исчерпания
возвращает `(0, ErrClosed)`. `Put` после закрытия, включая ожидавший
место вызов, возвращает `ErrClosed`. Это ненулевая sentinel-ошибка,
которую можно проверить через `errors.Is`.

Если `Put` выполняется одновременно с `Close`, элемент либо принят
до закрытия и потом доступен через `Get`, либо отклонён с
`ErrClosed`. Паника и потеря принятого элемента недопустимы.

Для хранения элементов используйте обычную структуру данных с памятью
`O(capacity)`. Защитите общее состояние мьютексом, а для ожидания
элемента и свободного места используйте `sync.Cond`. Каналы запрещены
в том числе для хранения элементов. После каждого пробуждения
проверяйте нужное условие снова.

## Ограничения

- `capacity >= 1`.
- Используйте стандартную библиотеку Go.
- Отмена через `context.Context` здесь не требуется.
- Не применяйте `time.Sleep` или активное ожидание для синхронизации.

## Пример

`start P=Put(2)` запускает вызов без ожидания, `join P` ждёт его
завершения. Остальные команды выполняются последовательно.

```text
Вход: capacity=1; Put(1); start P=Put(2); дождаться блокировки P;
      Get(); join P; Close(); Get(); Get()
Выход: (1, nil); P=nil; (2, nil); (0, ErrClosed)
```
