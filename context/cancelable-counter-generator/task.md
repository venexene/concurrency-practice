# 032. Генератор, который можно остановить

**Сложность:** Easy

**Темы:** `context.Context`, отмена заблокированной отправки, закрытие канала

## Условие

Реализуйте функцию:

```go
func Count(ctx context.Context) <-chan int
```

`Count` возвращает небуферизованный канал и запускает одну горутину,
которая последовательно отправляет `0, 1, 2, ...`. Каждое следующее
число появляется только после успешной отправки предыдущего. Значения
не должны пропускаться или повторяться, пока контекст активен.

Когда `ctx` отменяется, генератор прекращает работу и **закрывает
выходной канал**. Он должен завершиться и тогда, когда потребитель
перестал читать и горутина ждёт возможности отправить значение. Если
отмена пересеклась с попыткой отправки, получатель может увидеть
не более одного последнего значения после отмены; затем канал должен
закрыться. Если контекст был отменён ещё до вызова `Count`, канал
закрывается без значений.

## Ограничения

- Используйте одну обслуживающую горутину; не накапливайте бесконечный
  поток заранее.
- Канал небуферизованный и принадлежит генератору. Вызывающий код
  его не закрывает.
- `ctx` не равен `nil`. Для задания порядка событий не используйте
  `time.Sleep` или активное ожидание.

## Примеры

```text
Вход: ch := Count(ctx); получить два значения; cancel(); дождаться закрытия ch
Выход: значения [0, 1]; затем ch закрыт, горутина завершена
```

```text
Вход: ch := Count(ctx); не читать ch; cancel(); дождаться закрытия ch
Выход: ch закрыт, горутина завершена
```

```text
Вход: ctx отменён; ch := Count(ctx); дождаться закрытия ch
Выход: ch закрыт без значений
```
