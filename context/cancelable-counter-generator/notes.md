# 032. Генератор, который можно остановить

## Инсайт

Отправку в небуферизованный канал можно поставить в один `select` с
`ctx.Done()`: когда потребитель перестал читать, отмена всё равно
позволяет обслуживающей горутине выйти. Выходной канал нужно закрыть
самостоятельно.

## Решение

`Count` создаёт небуферизованный канал и одну горутину. В начале она
проверяет, не отменён ли уже контекст. Затем отправляет `0, 1, 2, ...`
через `select`, в котором есть ветка отмены. После каждой отправки
повторно проверяет отмену и, если она произошла, закрывает канал.
Ветка отмены основного `select` тоже закрывает канал. После отправки
без отмены счётчик увеличивается.

На каждое значение приходится `O(1)` работы; память — `O(1)` без
накопления потока. Создаётся одна горутина, которая ждёт готового
получателя или отмены.

## Что пошло не так

- Раньше при выходе по `ctx.Done()` канал `ch` оставался открытым.
  После отмены горутина завершалась, а потребитель ждал закрытия
  бесконечно. Теперь обе ветки выхода закрывают канал; тесты больше
  не упираются в сторожевой таймер.
- Раньше после отмены генератор мог снова и снова выбирать отправку,
  если получатель постоянно готов: `select` не отдаёт приоритет
  `ctx.Done()`. Теперь проверка после каждой успешной отправки
  ограничивает такой сценарий одним последним значением.
- Раньше контекст, отменённый до вызова `Count`, мог дать значение
  `0`: к моменту основного `select` одновременно были готовы отмена
  и получатель. Теперь отдельная проверка перед циклом закрывает
  канал без отправки для заранее отменённого контекста.

## Что важно запомнить

- Возврат из горутины не закрывает канал автоматически. Закрытие
  выхода — часть контракта генератора.
- `select` с двумя готовыми ветками выбирает одну из них без
  приоритета. Проверки отмены до цикла и после отправки ограничивают
  случаи, где можно наблюдать последнее значение.
- Небуферизованная отправка должна учитывать отмену, иначе генератор
  может застрять, когда потребитель перестанет читать.

## Проверка

Тесты проверяют последовательность `0, 1, 2, ...`, закрытие после
отмены, отмену без продолжающего чтение потребителя и контекст,
отменённый до вызова `Count`. При отмене после запуска допускается
не более одного последнего значения. Ожидание закрытия ограничено
сторожевым таймером.

`go test -race -count=100 -timeout=30s ./context/cancelable-counter-generator`
прошёл без обнаруженных гонок и зависаний. Многократный запуск не
доказывает корректность при каждом возможном расписании горутин.

## Оценка

По анализу кода и выполненным тестам ошибок относительно `task.md`
не обнаружено. Канал закрывается после отмены, включая случай
заблокированной отправки; заранее отменённый контекст не даёт значений.
