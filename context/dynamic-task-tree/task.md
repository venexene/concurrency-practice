# 040. Группа с динамическими дочерними задачами

**Сложность:** Hard

**Темы:** динамическое дерево задач, общий контекст, первая ошибка, завершение работы

## Условие

Операция начинается с одной задачи, но заранее неизвестно,
сколько работы она породит. Например, обработчик получает список
каталогов и запускает задачу для каждого, а те находят вложенные
каталоги и запускают новые задачи.

Нужно выполнить всё дерево как одну операцию: дождаться всех задач,
а при первой ошибке сообщить остальным об отмене и дождаться их
остановки. Завершение исходной задачи ещё не означает завершение
всего дерева.

Определите тип задачи и реализуйте функцию:

```go
type Task func(
    ctx context.Context,
    spawn func(child Task) error,
) error

func RunTree(ctx context.Context, root Task) error
```

Также определите ошибку `ErrClosed`, которую можно проверять
через `errors.Is`. Вспомогательные типы определите самостоятельно.

## Выполнение дерева

`root` — начальная задача. Каждая задача получает общий контекст
операции и свою функцию `spawn`. Через неё можно запускать дочерние
задачи, а дочерние задачи могут тем же способом создавать потомков.

Все задачи получают один общий дочерний контекст, связанный с `ctx`.
Он сохраняет значения и ограничения родителя. Отмена всего дерева
не должна отменять исходный родительский контекст.

`spawn(child)` принимает задачу к выполнению и возвращает `nil`,
не дожидаясь её завершения. Принятая задача запускается конкурентно
ровно один раз и получает собственную функцию `spawn`.
Возвращённый `nil` означает принятие задачи, а не её успешное завершение.

Если дочерняя задача позже вернёт ошибку, она участвует в выборе
общего результата `RunTree`. Сам вызов `spawn` не ждёт этой ошибки.
Родителю не требуется отдельно ждать потомков: за завершение
всего дерева отвечает `RunTree`.

`RunTree` возвращается только после завершения `root` и всех принятых
задач, включая потомков, добавленных после возврата `root`.
При отсутствии ошибок и внешней отмены результат — `nil`.

Например, возможен такой порядок:

```text
root запускает A и возвращается
A продолжает работать, запускает B и возвращается
B завершает работу
только теперь RunTree может вернуться
```

## Время жизни spawn

Функция `spawn`, переданная конкретной задаче, принадлежит этой
задаче. Ею можно пользоваться только до завершения владельца.
Если сохранить её и вызвать после возврата владельца,
вызов должен вернуть `ErrClosed` и не запускать переданную задачу.

Завершение родителя не закрывает функцию `spawn` его ещё работающего
потомка. Поэтому в примере выше A может создать B после завершения
`root`, используя свой `spawn`.

Если владелец уже завершён, возвращайте `ErrClosed`, даже если
всё дерево тоже отменено. Если владелец ещё работает, но дерево
уже отменено, возвращайте выбранную ошибку отмены дерева.

## Ошибки и отмена

Первая зарегистрированная ошибка одной из задач отменяет общий
контекст операции и становится результатом `RunTree`.
Задачи, которые уже запущены, должны отреагировать на отмену
и завершиться. `RunTree` ждёт их возврата перед своим выходом.

Внешняя отмена `ctx` участвует в том же выборе: если она
зарегистрирована первой, общим результатом становится `ctx.Err()`.
Это может быть `context.Canceled` или `context.DeadlineExceeded`.
Если `ctx` уже отменён при входе, верните его ошибку без запуска `root`.

После выбора ошибки новые задачи не принимаются. Вызов `spawn`
ещё работающего владельца возвращает выбранную ошибку и не запускает
`child`. Например, после ошибки B с `ErrB` работающая A получает
`ErrB` при попытке создать C.

Последующие ошибки не заменяют выбранную. В частности, ошибки
`context.Canceled`, возвращённые задачами в ответ на отмену,
не должны затереть первоначальную `ErrB`.

Если несколько ошибок или внешняя отмена происходят конкурентно
без заданного порядка, победителем может стать любое из этих событий,
зарегистрированное первым. Выбирать ошибку по глубине дерева,
порядку запуска или имени задачи не нужно.

Если `spawn` конкурирует с отменой или завершением своего владельца,
он может успеть принять задачу до закрытия возможности запуска
либо вернуть соответствующую ошибку. Принятую задачу необходимо
учесть и дождаться её завершения. При отказе задача не выполняется.

Отмена не останавливает произвольную функцию принудительно.
Она сообщает задачам, что пора завершить работу. Ранний возврат
`RunTree` при ещё работающих задачах нарушает условие.

## Ограничения

- `ctx`, `root` и задачи, передаваемые в `spawn`, не равны `nil`.
- Не более `10^4` задач, включая `root`.
- Задачи реагируют на отмену своего контекста и завершаются
  без паники. Обработка паник не требуется.
- `spawn` должен быть безопасен при конкурентных вызовах,
  включая вызовы одной сохранённой функции из нескольких горутин.
  Ограничение времени жизни владельца сохраняется.
- Отказ `spawn` сам по себе не является новым результатом задачи.
  Если задача возвращает эту ошибку, её возврат обрабатывается
  по общим правилам.
- После возврата `RunTree` не должно оставаться работающих задач
  дерева или незавершённой служебной работы; ресурсы контекста
  операции должны быть освобождены.
- Используйте стандартную библиотеку Go. Не задавайте порядок
  через `time.Sleep` и не используйте активное ожидание.

## Примеры

```text
Вход: root запускает A и возвращает nil;
      A после этого запускает B и возвращает nil; B возвращает nil
Результат: RunTree возвращает nil только после завершения B
```

```text
Вход: root запускает A и возвращает nil;
      A запускает B; B возвращает ErrB;
      A реагирует на отмену и возвращает context.Canceled
Результат: ErrB; root, A и B завершены до возврата RunTree
```

```text
Вход: root и A работают; отменить внешний ctx;
      задачи реагируют на отмену и завершаются
Результат: context.Canceled; все принятые задачи завершены
```

```text
Вход: B возвращает ErrB; после регистрации этой ошибки
      ещё работающая A вызывает свой spawn(C)
Результат: spawn возвращает ErrB; C не запускается;
           RunTree после завершения остальных задач возвращает ErrB
```

```text
Вход: root сохранила свой spawn и завершилась;
      A всё ещё работает; вызвать сохранённый spawn(C)
Результат: ErrClosed; C не запускается;
           собственный spawn задачи A всё ещё доступен до её возврата
```

```text
Вход: внешний ctx уже отменён до вызова RunTree
Результат: context.Canceled; root не вызывается
```
