# 037. Изолированные ветви запроса

**Сложность:** Medium

**Темы:** дерево контекстов, независимые ветви, причины отмены

## Условие

Один запрос запускает несколько независимых операций, например поиск
в базе и обращение к внешнему сервису. Каждую операцию нужно уметь
отменить отдельно. Также нужна общая отмена, которая останавливает
все операции запроса и запрещает запуск новых активных ветвей.

Реализуйте структуру `Scope`, создаваемую от родительского контекста,
и её методы. Для конструктора используйте имя `NewScope`:

```go
func NewScope(parent context.Context) *Scope

func (s *Scope) Child(name string) context.Context
func (s *Scope) CancelChild(name string, cause error)
func (s *Scope) CancelAll(cause error)
```

Поля структуры определите самостоятельно.

`Child(name)` возвращает контекст именованной ветви. При первом
обращении ветвь создаётся, при повторном — возвращается тот же
контекст, даже если он уже отменён. Ветви наследуют значения,
дедлайн и отмену `parent`.

`CancelChild(name, cause)` отменяет указанную ветвь с переданной
причиной. Другие ветви и родительский контекст продолжают работать.
Причину отмены должно быть возможно получить через `context.Cause`.

`CancelAll(cause)` отменяет все существующие ветви. Ветви, впервые
созданные после этого вызова, тоже должны быть сразу отменены
с причиной общей отмены. Родительский контекст этот метод не отменяет.

Первая отмена каждой ветви определяет её причину окончательно.
Например, если ветвь A сначала отменили с `ErrA`, а затем вызвали
`CancelAll(ErrStop)`, причиной A остаётся `ErrA`. Повторные отмены
не меняют уже установленную причину. Отмена родителя также
распространяется на все ветви, включая созданные позднее.

Пока ветвь активна, её `Err()` и `context.Cause` возвращают `nil`.
При отмене через методы `Scope` её `Done()` закрывается,
`Err()` возвращает `context.Canceled`, а `context.Cause` — причину
отмены. Для `cause == nil` причиной становится `context.Canceled`.

## Ограничения

- `parent` не равен `nil`.
- Разные ветви имеют разные имена. Повторное обращение к одному
  имени обозначает ту же ветвь, а не создание новой.
- В сценариях задачи `CancelChild` вызывается для уже созданной ветви.
- Все методы должны быть безопасны при конкурентных вызовах,
  включая одновременное создание ветвей и общую отмену.
- Если отмены происходят конкурентно без заданного порядка,
  допустима причина события, зарегистрированного первым.
- Используйте стандартную библиотеку Go и `context.Cause`.
- Не задавайте порядок через `time.Sleep` и не используйте
  активное ожидание.

## Примеры

```text
Вход: создать A и B; CancelChild("A", ErrA)
Результат: A отменена, context.Cause(A) == ErrA;
           B и parent остаются активными
```

```text
Вход: создать A и B; CancelChild("A", ErrA); CancelAll(ErrStop)
Результат: context.Cause(A) == ErrA; context.Cause(B) == ErrStop;
           обе ветви отменены
```

```text
Вход: CancelAll(ErrStop); затем Child("C")
Результат: C сразу отменена, context.Cause(C) == ErrStop
```

```text
Вход: A = Child("A"); отменить A; снова вызвать Child("A")
Результат: возвращён тот же контекст A; ветвь не запускается заново
```

```text
Вход: создать A и B; отменить parent с причиной ErrParent;
      затем создать C
Результат: A, B и C отменены с причиной ErrParent
```
