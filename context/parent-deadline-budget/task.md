# 033. Родительский дедлайн

**Сложность:** Easy

**Темы:** `context.WithTimeout`, наследование дедлайна, освобождение ресурсов

## Условие

Реализуйте функцию:

```go
func CallWithBudget(
    parent context.Context,
    budget time.Duration,
    f func(context.Context) error,
) error
```

Создайте дочерний контекст от `parent` с ограничением времени `budget`
и **синхронно** передайте его в `f`. Верните ошибку, которую вернула
`f`. После завершения `f` освободите ресурсы дочернего контекста:
его отменяющая функция должна быть вызвана и при успешном возврате,
и при ошибке.

Эффективный дедлайн дочернего контекста — более ранний из дедлайна
`parent` и момента `budget` после создания дочернего контекста.
Большой `budget` не продлевает более ранний дедлайн родителя.
Отмена `parent` также отменяет дочерний контекст. `f` получает именно
дочерний контекст и может наблюдать его `Deadline`, `Done`, `Err` и
значения родителя. Функция не запускает `f` в отдельной горутине и
возвращается только после её завершения.

## Ограничения

- `budget > 0`; `parent` и `f` не равны `nil`.
- В сценариях ожидания `f` реагирует на `ctx.Done()` и возвращает
  `ctx.Err()`. Она не обязана прерываться без собственного участия.
- Не используйте `time.Sleep` для задания порядка событий. В тестах
  дедлайны можно проверять с управляемым временем.
- Используйте стандартную библиотеку Go.

## Примеры

```text
Вход: parent истекает через 30 ms; budget=100 ms;
      f ожидает Done и возвращает Err
Выход: f видит дедлайн parent; через 30 ms возвращается
       context.DeadlineExceeded
```

```text
Вход: parent истекает через 100 ms; budget=20 ms;
      f ожидает Done и возвращает Err
Выход: через 20 ms возвращается context.DeadlineExceeded
```

```text
Вход: parent активен; f сразу возвращает ErrWork
Выход: ErrWork; после возврата дочерний контекст отменён
```
