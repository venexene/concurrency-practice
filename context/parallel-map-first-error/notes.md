# 034. Параллельный map с первой ошибкой

## Инсайт

Для каждого элемента запускаю отдельную горутину и записываю результат
по его индексу. `WaitGroup` позволяет дождаться всех обработчиков, а
`sync.Once` — зарегистрировать только одно первое событие ошибки и
отменить общий дочерний контекст.

## Решение

Создаю дочерний контекст `cCtx` и срез результатов длины `len(nums)`.
Для каждого индекса запускаю горутину. Перед вызовом `f` она проверяет
отмену, затем передаёт обработчику `cCtx` и свой элемент. При ошибке
через `sync.Once` сохраняю её в буферизованном канале и отменяю
`cCtx`. После `wg.Wait()` возвращаю первую зарегистрированную ошибку
с `nil` вместо результата либо весь срез результатов в порядке входа.

Для `n` элементов создаётся `n` горутин, дополнительные память и
работа по запуску — `O(n)`. Общее время зависит от работы самого
медленного обработчика и его завершения после отмены.

## Что пошло не так

- Сначала сигнатура принимала `f func(int) (int,error)` вместо
  `f func(context.Context,int) (int,error)`. Контрактные тесты не
  компилировались. Теперь сигнатура совпадает с условием.
- После изменения сигнатуры я передавал в `f` исходный `ctx`, но при
  первой ошибке отменял только дочерний `cCtx`. Например, `f(2)`
  возвращала ошибку, а `f(1)` и `f(3)` продолжали ждать отмены своего
  аргумента; `wg.Wait()` зависал. Тест первой ошибки завершался по
  сторожевому таймеру. Теперь в `f` передаётся `cCtx`, и этот тест
  проходит.
- Раньше при ошибке возвращался `[]int{}` — пустой, но ненулевой
  срез. Условие требует `(nil, err)` без частичного результата.
  Теперь возвращается `nil`.

## Что важно запомнить

- Контекст отменяет работу лишь тогда, когда работающий обработчик
  сам наблюдает его `Done`; вызванную `f` нельзя остановить извне.
- `WaitGroup` должен дождаться всех уже запущенных обработчиков и при
  ошибке, и при внешней отмене.
- Запись разных горутин в разные индексы заранее выделенного среза
  допустима, если читать общий результат только после `Wait`.
- В Go 1.25 переменная `i` в цикле `for i := ...` отдельная для каждой
  итерации; захват `i` в замыкании здесь сам по себе не ошибка.

## Проверка

Тесты проверяют пустой вход, параллельный запуск и порядок результатов,
первую ошибку с отменой и ожиданием всех обработчиков, а также внешнюю
отмену. `go test -race -count=10 -timeout=30s
./context/parallel-map-first-error` прошёл без ошибок и сообщений о
гонках. Тесты не доказывают корректность для каждого возможного
расписания горутин.

## Оценка

По анализу текущего кода и выполненным тестам ошибок относительно
`task.md` не обнаружено.
