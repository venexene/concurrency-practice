# 039. Отменяемое ожидание версии

**Сложность:** Hard

**Темы:** версии состояния, конкурентные обновления, отменяемые ожидания

## Условие

Сервис хранит строковое значение, которое время от времени обновляется.
Клиент уже видел определённую версию и хочет дождаться более новой.
Несколько клиентов могут ждать одновременно, а обновления могут
приходить в любой момент, в том числе прямо во время начала ожидания.

Реализуйте структуру `Versioned` с конструктором и методами:

```go
func NewVersioned(initial string) *Versioned

func (v *Versioned) Set(value string) error
func (v *Versioned) WaitNext(
    ctx context.Context,
    afterVersion uint64,
) (value string, version uint64, err error)
func (v *Versioned) Close()
```

Также определите ошибку `ErrClosed`, доступную вызывающему коду.
Поля структуры определите самостоятельно.

## Значение и версия

Сразу после создания объект содержит `initial` с версией `0`.
Каждый успешный `Set` заменяет значение и увеличивает версию на один.
Даже запись той же строки считается обновлением и увеличивает версию.
Успешный `Set` возвращает `nil`.

Значение и версия образуют одну целостную пару. Например, после
`Set("b")`, создавшего версию `1`, нельзя вернуть строку `"a"`
с версией `1`: такой пары в объекте не было.

## Ожидание обновления

`afterVersion` — номер версии, после которой клиент хочет увидеть
обновление. `WaitNext` должен вернуть пару с версией **строго больше**
этого номера.

Если подходящая версия уже есть, ждать следующего `Set` не нужно.
Если текущая версия меньше или равна `afterVersion`, вызов ждёт
подходящего обновления, отмены `ctx` или закрытия объекта.
`afterVersion` может быть больше текущей версии: тогда одного
обновления может оказаться недостаточно.

Промежуточные версии можно пропускать. Если клиент ждёт после версии
`0`, а объект уже обновился до версии `3`, допустимо вернуть пару
версии `3`. Не требуется передавать клиенту каждое обновление
или хранить историю значений.

Ожидания независимы. Одно обновление может позволить завершиться
нескольким клиентам; получение результата одним клиентом не должно
лишать результата остальных.

Обновление не должно потеряться между проверкой версии и началом
ожидания. Если `Set` сделал версию подходящей и больше обновлений
не было, уже начавшийся `WaitNext` не должен навсегда остаться ждать
ещё одного `Set`.

## Отмена и закрытие

Если ожидание прерывается отменой или дедлайном `ctx`, верните
`("", 0, ctx.Err())`. Отмена одного клиента не отменяет другие
ожидания и не закрывает объект. Уже отменённый контекст не должен
заставлять вызов ждать будущих событий.

После возврата отменённого вызова связанные именно с ним ресурсы
ожидания должны быть освобождены. Многократное создание и отмена
ожиданий не должно накапливать оставшиеся подписки или горутины.
Возврат строки и версии с ошибкой не означает частичного успеха:
при любой ошибке возвращайте `""` и `0`.

`Close` закрывает объект и будит все незавершённые ожидания.
Они завершаются с `ErrClosed`, если до закрытия ещё не был
зафиксирован другой допустимый исход. Повторные вызовы `Close`
безопасны.

После закрытия:

- `Set` возвращает `ErrClosed` и не меняет состояние.
- Новые вызовы `WaitNext` возвращают `("", 0, ErrClosed)`;
  сохранённое значение не выдаётся даже при подходящей версии.
- Новые ожидания обновлений не создаются.

Если обновление, отмена ожидания и закрытие происходят конкурентно
без заданного порядка, допустим исход, зафиксированный первым.
Не требуется всегда предпочитать успех или всегда предпочитать
ошибку в такой гонке. Успешный исход в любом случае должен содержать
целостную пару с версией строго больше `afterVersion`.

## Ограничения

- `ctx` не равен `nil`; строка может быть пустой.
- Версии помещаются в `uint64` и не переполняются.
- Методы должны быть безопасны при конкурентных вызовах,
  включая одновременные `Set`, `WaitNext` и `Close`.
- До `10^5` вызовов и до `10^3` вызывающих горутин.
- Для проверки `ErrClosed` вызывающий код может использовать
  `errors.Is`.
- Используйте стандартную библиотеку Go. Не задавайте порядок
  через `time.Sleep` и не используйте активное ожидание.

## Примеры

```text
Вход: initial="a"; запустить WaitNext(ctx, 0); Set("b")
Результат: Set возвращает nil; ожидание получает ("b", 1, nil)
```

```text
Вход: initial="a"; Set("b"); Set("c"); WaitNext(ctx, 0)
Результат: ("c", 2, nil) без ожидания нового обновления
```

```text
Вход: initial="a"; запустить WaitNext(ctx, 2);
      Set("b"); Set("c"); Set("d")
Результат: после первых двух Set подходящей версии ещё нет;
           после третьего ожидание получает ("d", 3, nil)
```

```text
Вход: initial="a"; A и B ждут после версии 0;
      отменить контекст A; дождаться возврата A; Set("b")
Результат: A получает ("", 0, context.Canceled);
           B получает ("b", 1, nil)
```

```text
Вход: initial="a"; запустить WaitNext(ctx, 0); Close();
      затем Set("b") и новый WaitNext(ctx, 0)
Результат: оба ожидания получают ("", 0, ErrClosed);
           Set возвращает ErrClosed
```

```text
Вход: initial="a"; Set("a"); WaitNext(ctx, 0)
Результат: ("a", 1, nil); одинаковая строка не отменяет рост версии
```
