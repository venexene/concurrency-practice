# 038. Отмена подписчика, а не операции

**Сложность:** Medium

**Темы:** общая операция, независимые ожидания, отмена, сохранение результата

## Условие

Сервис один раз загружает данные из внешнего источника. Несколько
клиентов хотят получить результат этой загрузки и ждут его независимо.
Если один клиент отключился, прекращается только его ожидание:
сама загрузка продолжается для остальных клиентов.

Реализуйте структуру `SharedCall` с конструктором и методами:

```go
func NewSharedCall(
    serviceCtx context.Context,
    f func(context.Context) (string, error),
) *SharedCall

func (s *SharedCall) Await(waiterCtx context.Context) (string, error)
func (s *SharedCall) Close()
```

Поля структуры определите самостоятельно.

При создании объекта запустите `f` конкурентно ровно один раз.
Переданный в `f` контекст относится к общей операции: её должны
отменять отмена `serviceCtx` и вызов `Close`, но не отмена ожидания
отдельного клиента. Конструктор не ждёт завершения `f`.

`Await` ждёт результат общей операции либо отмену своего `waiterCtx`.
Если операция завершилась, метод возвращает строку и ошибку,
которые вернула `f`. Если ожидание отменено раньше получения
результата, метод возвращает пустую строку и `waiterCtx.Err()`.
Это не должно отменять `f` или мешать другим вызовам `Await`.
Операция продолжается даже тогда, когда у неё не осталось ожидающих
клиентов.

Результат `f`, включая ошибку, сохраняется. Все последующие вызовы
`Await` с активным контекстом получают этот же результат без нового
запуска `f`. Если `waiterCtx` уже отменён при входе в `Await`, верните
его ошибку сразу, даже если результат операции уже готов.

`Close` отменяет общую операцию и ждёт возврата `f`. Он должен
работать и до, и после завершения операции. Повторные и конкурентные
вызовы `Close` безопасны; каждый возвращается только после завершения
`f`. Закрытие не стирает сохранённый результат и не отменяет
`serviceCtx`.

Отмена общей операции не останавливает произвольную функцию
принудительно: `f` сама реагирует на свой контекст. Активные вызовы
`Await` после её завершения получают именно результат `f`.
Например, если она вернула `("", context.Canceled)`, этот результат
будет сохранён и передан ожидающим клиентам.

## Ограничения

- `serviceCtx`, `waiterCtx` и `f` не равны `nil`.
- `f` реагирует на отмену переданного контекста и завершается
  без паники.
- `Await` и `Close` должны быть безопасны при конкурентных вызовах.
- Если готовность результата и отмена ожидания происходят
  конкурентно без заданного порядка, допустим любой из этих исходов.
  Исключение — уже отменённый при входе `waiterCtx`.
- После завершения операции связанные с её контекстом ресурсы
  должны быть освобождены. После `Close` работа `f` завершена.
- Используйте стандартную библиотеку Go. Не задавайте порядок
  через `time.Sleep` и не используйте активное ожидание.

## Примеры

```text
Вход: создать SharedCall; A и B конкурентно вызывают Await;
      отменить контекст A; затем f возвращает ("v", nil)
Результат: A получает ("", context.Canceled), B получает ("v", nil);
           f вызвана один раз
```

```text
Вход: f завершилась с ("", ErrLoad); дважды вызвать Await
      с активными контекстами
Результат: оба вызова получают ("", ErrLoad); f не запускается повторно
```

```text
Вход: результат ("v", nil) уже сохранён;
      вызвать Await с уже отменённым контекстом
Результат: ("", context.Canceled)
```

```text
Вход: f ждёт отмены своего контекста и возвращает ctx.Err();
      вызвать Close, затем Await с активным контекстом
Результат: Close ждёт завершения f; Await получает ("", context.Canceled)
```
