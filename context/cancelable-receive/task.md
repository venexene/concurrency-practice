# 031. Отменяемое получение

**Сложность:** Easy

**Темы:** `context.Context`, `select`, закрытие канала

## Условие

Реализуйте функцию:

```go
var ErrClosed error

func Recv(ctx context.Context, in <-chan int) (int, error)
```

`Recv` ожидает значение из `in` или отмену `ctx`.

- Если получено значение, верните его и `nil`, включая значение `0`.
- Если канал закрыт и все ранее отправленные значения уже прочитаны,
  верните `0, ErrClosed`. `ErrClosed` должен быть отдельной ошибкой,
  распознаваемой через `errors.Is`.
- Если контекст отменён, верните `0, ctx.Err()`.

Если `ctx` **уже отменён при входе** в `Recv`, отмена имеет приоритет:
верните `ctx.Err()`, даже если в канале уже есть значение или он закрыт.
Если отмена и получение стали возможны после входа в функцию, любой
из этих исходов допустим. При наличии значения в закрытом буферизованном
канале сначала можно получить это значение; `ErrClosed` возвращается
лишь после исчерпания буфера.

## Ограничения

- `in == nil` означает ожидание только отмены контекста.
- `ctx` не равен `nil`; вызывающий код не закрывает канал повторно.
- Не создавайте дополнительных горутин и не используйте активное
  ожидание или `time.Sleep` для задания порядка событий.
- Функция не закрывает входной канал.

## Примеры

```text
Вход: in содержит [7], ctx активен; Recv(ctx, in)
Выход: (7, nil)
```

```text
Вход: in закрыт после отправки 0; Recv(ctx, in); Recv(ctx, in)
Выход: (0, nil); (0, ErrClosed)
```

```text
Вход: ctx отменён до вызова; in содержит [7]; Recv(ctx, in)
Выход: (0, context.Canceled)
Пояснение: значение 7 остаётся в канале.
```

```text
Вход: in=nil; начать Recv(ctx, in); затем отменить ctx
Выход: (0, context.Canceled)
```
