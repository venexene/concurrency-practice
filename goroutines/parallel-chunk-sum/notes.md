# 005. Параллельная сумма блоков

## Инсайт

Размер обычного блока — `q = len(nums)/k`, а первые
`r = len(nums)%k` блоков должны получить ещё по одному элементу.
Частичные суммы собираю через канал, после завершения всех горутин
закрываю его и складываю полученные значения.

## Что пошло не так

**Первый цикл захватывает общую `i`.** Объявил `var i int` до цикла, а внутри
горутины использую её для расчёта `start`. Пока горутина читает `i`, родитель
может перейти к следующей итерации и изменить её. В результате несколько
горутин берут один блок или пропускают другие. Например, тест с
`nums=[1,2,4,8,16]`, `k=3` получил `48` вместо `31`; с двумя элементами
и пятью блоками один запуск дал `0` вместо `3`. Race detector указал на
чтение `i` в горутине и запись в заголовке цикла.

Исправил: теперь `i` объявлена через `:=` в первом цикле. При указанной в
модуле версии Go 1.25 у каждой итерации своя `i`, как и `j` во втором цикле.
Заодно граница обычных блоков теперь начинается после всех `r` увеличенных
блоков: `r*(q+1) + j*q`. Повторная проверка сумм прошла без гонок.

## Что важно запомнить

- Для каждого блока границы должны вычисляться из его собственного номера,
  который уже не меняется после запуска горутины.
- Проверка `b < len(nums)` не исправляет неправильный `start`: она может
  предотвратить выход за границы слайса, но пропущенные числа не вернутся.
- Здесь `wg.Add(1)` стоит до запуска горутины, `Done()` вызывается при выходе,
  а канал закрывается после `wg.Wait()`. В этой части порядок завершения верный.
- Отдельная горутина ждёт `wg.Wait()` и закрывает `ch`, чтобы цикл `range`
  завершился. После `close(ch)` у неё нет другой работы. Создавать ещё один
  канал только ради ожидания её выхода здесь не нужно. Если хочется обойтись
  без неё, число отправок заранее известно: их ровно `k`.

## Проверка

Тесты охватывают пример, пустой вход, `k=1`, один элемент на блок,
`k > len(nums)`, несколько вариантов с остатком, отрицательные числа,
`k=1000`, неизменность входа и параллельные вызовы функции.

```sh
go test -race -timeout 30s ./goroutines/parallel-chunk-sum
```

После изменения циклов все тесты прошли, race detector гонок не нашёл.

## Оценка

Задача решена: суммы и разбиение корректны, рабочие горутины завершены,
заблокированных отправителей после возврата не остаётся.
