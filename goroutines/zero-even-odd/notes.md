# 003. Ноль, чётное, нечётное

## Инсайт

Передаю по каналам последнее выведенное число. `Zero` получает его, выводит 0
и отправляет следующее число в `Even` или `Odd`. После вывода число возвращается
в `Zero`, и начинается следующий круг.

Для завершения добавил отдельный `breakCh`. Когда последнее число уже выведено
и вернулось в `Zero`, закрываю этот канал. Оба остальных участника получают
сигнал завершения, даже если одному из них больше не достанется чисел.

## Решение

Начинаю с 0 в `zeroCh`. Значение в этом канале — последнее выведенное число,
поэтому при `val >= n` работа уже закончена. Иначе вывожу ноль, увеличиваю `val`
и выбираю канал по чётности.

`Even` и `Odd` ждут либо своё число, либо закрытие `breakCh`. После своего
`emit` возвращают число в `zeroCh`. Следующий участник получает ход только
после завершения предыдущего `emit`.

`n` не меняю, а `val` локальный: общего изменяемого счётчика здесь нет.
По числу вызовов `emit` работа — O(n), дополнительная память — O(1).
Методы вызываются в трёх горутинах; внутри них новые горутины не создаю.
Время работы самого `emit` зависит от переданной функции.

## Что пошло не так

В первом наброске перепутал каналы: при `val % 2 != 0` отправлял число
в `evenCh`. Например, 1 попадала бы в `Even`, хотя её должен выводить `Odd`.
Исправил: чётные идут в `evenCh`, нечётные — в `oddCh`. Тесты теперь проверяют
не только последовательность, но и то, какой метод вызвал `emit`.

## Что важно запомнить

- Одного `break` в `Zero` мало для остановки всех: `Even` и `Odd` могут ждать
  входные каналы. Закрытие общего сигнального канала будит обоих.
- `breakCh` закрывает только `Zero`, и только после возврата последнего числа.
  Значит, последний `emit` уже завершился, а новых чисел больше не будет.
- При `n=0` сразу закрываю `breakCh`, ничего не вывожу. При `n=1` `Even`
  не получает чисел, но всё равно завершает работу по этому сигналу.
- Буфер у `breakCh` для такого использования не нужен: в него ничего
  не отправляю, только закрываю. Это мелочь, на корректность не влияет.
- Четыре канала допустимы по условию. Текущий вариант с отдельным каналом
  завершения работает, уменьшать их число для решения задачи не требуется.

## Проверка

В `solution_test.go` проверяются:

- Все шесть порядков запуска при `n=0`, `1`, `2`, `3`, `4`, `5`, `9999`, `10000`.
- Ровно `2*n` вызовов в порядке `0,1,0,2,...,0,n` и правильный метод для
  каждого значения: нули — `Zero`, чётные — `Even`, нечётные — `Odd`.
- Одновременный старт при `n=1000`.
- Медленный `emit`: следующий вызов ждёт, а метод не возвращается, пока
  его собственный callback ещё работает.
- Независимость двух объектов и завершение всех трёх методов.

Используются каналы и `testing/synctest`, без задержек через `time.Sleep`.
Журнал теста защищён Mutex.

```sh
go test -race -timeout 30s ./goroutines/zero-even-odd
```

Все тесты прошли, race detector гонок не нашёл.

## Оценка

Задача решена. В текущей версии ошибок по условию не обнаружено.
