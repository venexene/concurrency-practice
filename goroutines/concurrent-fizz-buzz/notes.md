# 008. Конкурентный FizzBuzz

## Инсайт

Четыре метода делят один счётчик `cur`. Каждый метод отвечает только за
свою категорию чисел, а `sync.Cond` позволяет ждать своего хода.

## Решение

Каждый метод под мьютексом проверяет, относится ли текущий `cur` к его
категории. Если нет — ждёт через `cond.Wait()`. Если да — вызывает свой
callback, увеличивает `cur` и будит остальные методы. После обработки `n`
следующее пробуждение позволяет всем увидеть `cur > n` и выйти.

## Что пошло не так

- **Проверял категорию по `n`, а не по текущему числу.** Сначала условия во
  всех четырёх методах использовали `f.n % ...`. Например, при `n=5` метод
  `Buzz` считал подходящим каждый ход и мог вызвать `emit()` для числа
  `1`, хотя первым должен сработать `Number(1)`. Правило FizzBuzz нужно
  применять к числу, которое сейчас обрабатывается. Исправил: теперь условия
  проверяют `f.cur`.
- **После изменения `cur` не пробуждал остальные методы.** `cond.Wait()`
  блокирует горутину до `Signal` или `Broadcast`, а такого вызова в наброске
  не было. При `n=1` метод `Number` выводил `1` и возвращался, а остальные могли
  навсегда остаться в `Wait`; вызывающий код зависал на `wg.Wait()`.
  Пробуждение требуется и при смене хода, и после последнего числа, чтобы
  методы без оставшейся работы тоже смогли завершиться. Исправил: после
  каждого увеличения `cur` вызывается `Broadcast()`.

Неиспользуемое поле `wg` внутри `FizzBuzz` удалено. Оно не было ошибкой
корректности.

## Что важно запомнить

- `cond.Wait()` освобождает мьютекс на время ожидания и снова захватывает его
  перед возвратом. Условие своего хода нужно проверять в цикле.
- Проверка номера и его изменение уже находятся под `cond.L`; это правильно
  защищает общее состояние. Callback тоже вызывается под мьютексом, поэтому
  вызовы `emit` не пересекаются.

## Проверка

Тесты проверяют `n=0`, случаи без некоторых категорий, переход на
`fizzbuzz` при 15, значения до `n=10_000`, разные порядки запуска методов,
одновременные экземпляры и отсутствие пересечения callbacks. Все четыре
метода должны завершиться, иначе тестовый запуск остановится по таймауту.

```sh
go test -race -count=1 -timeout 30s ./goroutines/concurrent-fizz-buzz
```

Тесты прошли, race detector гонок не нашёл. Ранее `go run -race` при `n=15`
тоже вывел ожидаемую последовательность.

## Оценка

Задача решена: проверенные значения дают нужный порядок, методы завершаются,
гонок не обнаружено.
