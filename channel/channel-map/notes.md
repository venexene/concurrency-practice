# 013. Преобразование потока

## Инсайт

`Map` — потоковый этап конвейера. Он не ждёт накопления всех входных данных:
каждое значение читается из `in`, преобразуется `f` и сразу передаётся дальше.
Цикл `range` естественно определяет момент завершения входного потока, после
чего нужно закрыть выходной канал.

## Оценка решения

Решение корректное: отдельная горутина читает `in` до закрытия, применяет
`f(n)` к каждому значению, отправляет результат и затем закрывает свой
выходной канал. Оно обрабатывает поток постепенно, сохраняет порядок и не
накапливает входные данные в памяти.

Как и у других неотменяемых конвейерных этапов, досрочный уход потребителя
оставит горутину заблокированной на отправке; для такой ситуации API должен
принимать `context.Context` или канал `done`.

## Что важно запомнить

- Выходной канал закрывает его единственный отправитель — горутина внутри
  `Map`.
- Закрытие `in` не закрывает `out` автоматически: это нужно сделать явно.
- Обработка по одному элементу сохраняет порядок и использует `O(1)`
  дополнительной памяти.
- Для `n` значений время работы — `O(n)` плюс стоимость вызовов `f`.

## Проверка

В `solution_test.go` проверяются преобразование и порядок, вызов `f` ровно
один раз на элемент, пустой вход, закрытие результата и независимые
одновременные вызовы.

```sh
go test -race ./channel/channel-map
```
