# 019. Маршрутизация по предикату

**Сложность:** Medium

**Темы:** каналы, `select`, владение каналами, отмена

## Условие

Реализуйте функцию:

```go
func Partition(ctx context.Context, in <-chan int, pred func(int) bool) (yes, no <-chan int)
```

Функция должна сразу вернуть два канала только для чтения. В отдельной
горутине читайте значения из `in` и вызывайте `pred` ровно один раз для
каждого обработанного значения. Если результат `true`, отправьте значение
только в `yes`; если `false` — только в `no`. Внутри каждого выхода сохраняйте
порядок соответствующих входных значений.

Выходы небуферизованные. Пока получатель выбранного выхода не примет значение,
не переходите к следующему входному значению. Два потребителя читают `yes` и
`no` конкурентно. Когда вход исчерпан, закройте оба выхода.

При отмене `ctx` прекратите обработку и закройте оба выхода, даже если
отправка в выбранный канал заблокирована. Если отмена совпала с готовой
отправкой, текущее значение может быть доставлено или пропущено; новых
значений после завершения обработки не должно быть.

## Ограничения

- `pred` не равен `nil` и завершается без паники.
- Дополнительная память — `O(1)` без учёта двух каналов и вспомогательной
  горутины; не накапливайте весь поток в слайсе.
- Не закрывайте входной канал: им владеет отправитель. Для завершения без
  отмены отправитель в итоге закрывает `in`.
- Вызовы `pred` выполняются последовательно в горутине обработки; отмена не
  может прервать уже начавшийся вызов `pred`.
- Используйте стандартную библиотеку Go. Не применяйте `time.Sleep` или
  активное ожидание для синхронизации.

## Примеры

```text
Вход: in=[1, 2, 3, 4], pred(x)=x%2==0; затем close(in)
Выход: yes=[2, 4], no=[1, 3]; затем оба канала закрыты
```

```text
Вход: in отправил 7, pred(7)=true, читатель yes отсутствует; cancel(ctx)
Выход: оба выхода закрываются без ожидания читателя yes
```
