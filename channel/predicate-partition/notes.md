# 019. Маршрутизация по предикату

## Инсайт

Каждое значение нужно направить ровно в один выход. Один последовательный
обработчик сохраняет порядок внутри `yes` и `no`, а отправка через
небуферизованный канал даёт обратное давление: пока выбранный читатель не
примет значение, следующее не обрабатывается.

## Решение

Я создаю два небуферизованных выхода и одну горутину. Она читает из `in`,
вызывает `pred` для значения, выбирает `yesCh` либо `noCh` и отправляет туда
значение через `select` с `ctx.Done()`. При закрытии входа или отмене горутина
закрывает оба выхода. Переменная `ch` используется только внутри этой
горутины, поэтому конкурентной записи в неё нет.

Для `n` обработанных значений время работы — `O(n)` плюс время вызовов `pred`
и ожидание читателей. Дополнительная память — `O(1)`, вспомогательная
горутина одна.

## Что важно запомнить

- Выбранный медленный выход останавливает обработку следующего элемента, а
  второй выход не получает копию этого значения.
- Отправка в выбранный канал должна прерываться по `ctx.Done()`, иначе
  отмена не сможет завершить горутину при отсутствии читателя.
- Владелец выходов закрывает их после завершения работы; входной канал здесь
  чужой и не закрывается.
- `pred` не принимает контекст. Уже начавшийся вызов не прерывается отменой,
  поэтому его завершение — часть условия задачи.

