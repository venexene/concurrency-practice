# 016. Взять первые n

## Инсайт

Нужно ограничить число операций чтения, а не только длину результата. Если
прочитать один лишний элемент, он уже исчезнет из канала и вызывающий код не
сможет получить остаток. Чтение в форме `val, ok := <-in` позволяет отдельно
заметить закрытие канала, не путая его с нулевым значением.

## Решение

Я делаю до `n` чтений в цикле. Если `ok == false`, выхожу раньше; иначе
добавляю значение в результат. Цикл не запускается при `n == 0`. Слайс сразу
создаётся с ёмкостью `n`, поэтому время работы — `O(k)`, где `k` — число
прочитанных элементов, а выделенная память — `O(n)` даже при раннем закрытии
канала. Вспомогательные горутины не создаются. Ожидание следующего значения
зависит от отправителя и в эту оценку времени не входит.

## Что важно запомнить

- Остановка после `n` значений оставляет остальные элементы в канале.
- Закрытие входа позволяет завершить чтение раньше `n`; сам `Take` канал не
  закрывает.
- Ноль — полноценное значение. О завершении канала сообщает `ok == false`.
- Если вход остаётся открытым и значений недостаточно, чтение будет ждать.
  После раннего возврата из `Take` производителю нужен отдельный сигнал
  остановки, если он может заблокироваться на дальнейших отправках.

## Проверка

В `solution_test.go` проверяются `n == 0` без чтения, обычный случай с
непрочитанным остатком, раннее закрытие, пустой закрытый канал и поток через
небуферизованный канал.

```sh
go test -race -timeout 15s ./channel/take-first-elements
```

Проверка прошла.

## Оценка

Для заданного контракта ошибок не обнаружено. Тесты проверяют перечисленные
случаи; успешный запуск не доказывает корректность при любом расписании
горутин.
