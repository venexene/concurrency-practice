# 018. Разветвитель с гарантией доставки

**Сложность:** Medium

**Темы:** каналы, `select`, backpressure, отмена

## Условие

Реализуйте функцию:

```go
func Tee(ctx context.Context, in <-chan int) (left, right <-chan int)
```

Функция возвращает два канала только для чтения. Для каждого значения из `in`
отправьте по одной копии в `left` и `right`. В каждом выходе порядок должен
совпадать с порядком входа. Оба выхода следует закрыть, когда входной канал
закрыт и все прочитанные значения доставлены.

Выходы небуферизованные. Если один из потребителей медленный, обработка
текущего значения ждёт его и не накапливает весь входной поток в памяти.
Потребители читают оба выхода конкурентно: последовательное вычитывание
одного выхода до закрытия перед чтением другого может заблокировать работу.

При отмене `ctx` прекратите обработку и закройте оба выхода, даже если
горутина в этот момент ждёт готовности одного из потребителей. Значение,
обработка которого уже началась, может успеть попасть только в один из
выходов; после отмены не требуется доводить доставку этого значения до обоих.

## Ограничения

- Выходные каналы небуферизованные; дополнительная память — `O(1)` без учёта
  двух каналов и вспомогательной горутины.
- Не закрывайте входной канал: им владеет отправитель. Для завершения без
  отмены отправитель в итоге закрывает `in`.
- Порядок доставки в `left` и `right` не важен, но внутри каждого выхода
  значения должны идти в исходном порядке.
- Используйте стандартную библиотеку Go. Не применяйте `time.Sleep`,
  активное ожидание или накопление всего потока в слайсе.

## Примеры

```text
Вход: in=[2, 5, 8], затем close(in); два потребителя читают параллельно
Выход: left=[2, 5, 8], right=[2, 5, 8]; затем оба канала закрыты
```

```text
Вход: in отправил 7; left прочитал 7; right не читает; cancel(ctx)
Выход: оба выхода закрываются без ожидания читателя right
```
