# 011. Генератор диапазона

## Инсайт

Канал — поток значений, а не готовая коллекция. `Range` создаёт канал,
запускает горутину-генератор и сразу возвращает канал вызывающему коду.
Горутина последовательно отправляет числа из `[lo, hi)`, а затем вызывает
`close(ch)`. Благодаря закрытию потребитель может читать поток через
`for n := range ch` и цикл завершится сам.

## Оценка решения

Решение корректное для поставленного контракта:

- выдаёт `lo, lo+1, ..., hi-1` в правильном порядке;
- не хранит диапазон целиком в памяти;
- возвращает канал сразу, не ожидая потребителя;
- закрывает канал и для непустого, и для пустого диапазона;
- наружу отдаётся `<-chan int`, поэтому вызывающий код не может случайно
  отправить значение или закрыть канал.

Важное ограничение: канал небуферизованный. Если потребитель прекратит чтение
раньше времени, горутина заблокируется на `ch <- i`. Это не ошибка в рамках
этой задачи, потому что API не принимает сигнал отмены; в отменяемом варианте
отправку нужно выбирать через `select` с `context.Done()` или `done`.

## Что важно запомнить

- Отправитель закрывает канал; получатель этого делать не должен.
- `close(ch)` выполняется после цикла, в том числе когда цикл не сделал ни
  одной итерации.
- Небуферизованная отправка синхронизирует генератор с потребителем и не
  позволяет генератору накопить весь диапазон в памяти.
- Время работы — `O(max(0, hi-lo))`, дополнительная память — `O(1)`, помимо
  одной горутины и самого канала.

## Проверка

В `solution_test.go` проверяются обычный, отрицательный и одноэлементный
диапазоны, равные и обратные границы, порядок значений, закрытие канала и
независимость нескольких одновременных вызовов.

```sh
go test -race ./channel/range-generator
```
