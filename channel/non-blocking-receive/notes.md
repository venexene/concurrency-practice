# 015. Неблокирующее чтение без потери состояния

## Инсайт

Одного значения `int` недостаточно, чтобы отличить прочитанный ноль от
закрытого канала. При чтении через `val, ok := <-ch` признак `ok` сообщает,
получено ли настоящее значение. Ветка `default` у `select` отдельно обозначает
ситуацию, когда чтение сейчас заблокировалось бы.

## Решение

Я читаю из канала в ветке `select`: при `ok == true` возвращаю `val` и
`"value"`, при `ok == false` — `0` и `"closed"`. Если чтение не готово,
возвращаю `"empty"`. За вызов читается не более одного значения. Время и
дополнительная память — `O(1)`; горутины не создаются.

## Что важно запомнить

- Закрытие канала не выбрасывает значения из буфера: чтение сначала забирает
  их, и только потом возвращает `ok == false`.
- Нулевое значение элемента и нулевое значение, полученное после закрытия,
  различаются по `ok`. Строковое состояние сохраняет это различие для
  вызывающего кода.
- Чтение из `nil`-канала никогда не готово, поэтому выбирается `default`.
- `"empty"` описывает состояние в момент попытки чтения. Сразу после возврата
  другой отправитель может передать значение или закрыть канал.

## Проверка

В `solution_test.go` проверяются открытые пустой и заполненный каналы,
`nil`-канал, отсутствие отправителя у небуферизованного канала, настоящий ноль,
порядок значений в закрытом буфере, закрытый пустой канал и одновременные
получатели.

```sh
go test -race -timeout 15s ./channel/non-blocking-receive
```

Проверка прошла.

## Оценка

В рамках указанного контракта ошибок не обнаружено. Тесты проверяют
перечисленные сценарии; успешный запуск не доказывает поведение при каждом
возможном расписании горутин.
