# 012. Собрать значения до закрытия канала

## Инсайт

Цикл `for n := range in` получает значения из канала, пока отправитель не
закроет его и не будут вычитаны все уже отправленные значения. Поэтому он
точно соответствует задаче: не нужно вести счётчик, отдельно проверять
`ok` или гадать, сколько значений ещё придёт.

Каждое полученное значение добавляется в слайс через `append`, так что порядок
в слайсе совпадает с порядком получения из канала.

## Оценка решения

Решение корректное для заданного контракта:

- читает поток полностью, включая буферизированные значения перед закрытием;
- сохраняет порядок;
- возвращает пустой ненулевой слайс для сразу закрытого канала;
- не закрывает чужой канал;
- тип `<-chan int` не позволяет функции по ошибке отправлять значения во
  входной канал или закрыть его.

Важно, что функция намеренно блокируется, пока производитель не закроет
канал. Если производитель забудет это сделать или будет передан `nil`-канал,
`Collect` не сможет завершиться. Для такого случая нужен другой контракт —
например, `context.Context` или отдельный канал отмены.

## Что важно запомнить

- Закрывать канал должен отправитель, а не получатель.
- Закрытие не удаляет уже отправленные значения: `range` прочитает их перед
  завершением.
- `range` по каналу завершится только после `close`; отсутствие новых
  отправок само по себе не является сигналом окончания.
- При `n` полученных значениях время работы — `O(n)`. Результирующий слайс
  занимает `O(n)` памяти.

## Проверка

В `solution_test.go` проверяются пустой и заполненный буферизированные каналы,
поток из небуферизованного канала, порядок значений, а также независимость
нескольких одновременных вызовов.

```sh
go test -race ./channel/collect-until-close
```
